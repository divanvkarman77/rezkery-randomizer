# Разбор предоставленных расширений

## Объём и метод

Восемь ZIP, 119 записей архивов вместе с каталогами, суммарно 1 114 037 байт в распакованном виде. Исходники изучены как данные: установочные команды из README не запускались, авторизация и массовый сбор сайта не выполнялись. Все 40 JS-файлов прошли `node --check`; ссылки manifest на локальные background, popup и иконки существуют. Это подтверждает синтаксис и комплектность указанных ресурсов, но не работоспособность функций в браузере.

Версии определялись по manifest и фактическому коду. Несколько README и заголовков интерфейса относятся к более ранним версиям.

SHA-256 исходных ZIP и сведения manifest находятся в [archive-inventory.json](archive-inventory.json). Указанные ниже пути относятся к файлам внутри присланных архивов, а не к текущему репозиторию.

## 1. Rezka Library Chrome 0.5.8 DomainFixed

Папка в ZIP: `Rezka-Library-Chrome-0.5.8-DomainFixed/`.

### Что реализовано

- Избранное аккаунта читается с `/favorites/`, затем обходятся отдельные папки и их страницы.
- Фильм отделён от принадлежности папке: есть `items`, `categories`, `memberships`. Один фильм может входить в несколько папок без копирования самой записи.
- `background.js:344` — `canonicalItemKey`: сначала `rezka:<числовой ID>`, затем путь; это устойчивее привязки к одному домену.
- `mergeItem` сохраняет существующие описания, оригинальные постеры и встроенные картинки при обновлении карточки.
- Постеры кэшируются в отдельной IndexedDB `RezkaLibraryPosterCache`; ключ связан с фильмом.
- Фоновый `job.html` выполняет сбор, обогащение описаний, поиск оригиналов и операции с аккаунтом независимо от popup.
- `job.js:136` — `postFavorites`: запросы в `/ajax/favorites/`; `add_cat` создаёт папку, `add_post` добавляет фильм.
- Перед добавлением загружаются существующие ID закладок. Категории аккаунта сопоставляются с локальными по имени.
- `background.js:646` — импорт Desktop FAV с полями `id`, `title`, `url`, `poster`, `entity`, `entity_type`, `time`, `has_trailer`; создаются папка и связи.
- `background.js:689` — резервная копия `format: "rezka-library"`, `formatVersion: 4`, `items/categories/memberships`.
- Несколько HTML-представлений, описания по наведению, увеличенные постеры, получение оригиналов и обновление существующего HTML.

### Что переносить с изменениями

`normalizeItem` переводит URL на `rezka.fi`; экспорт использует другой заранее выбранный домен. Для общего приложения идентичность фильма нужно хранить отдельно от адреса открытия и зеркала сеанса.

В `job.js` есть задержки порядка 120 мс при получении описаний, 180 мс между страницами папок и 350 мс между добавлениями. Их нельзя считать универсальным ограничителем нагрузки для объединённого приложения: одновременно могут работать и другие модули. Нужна одна общая очередь.

Сопоставление папок только по имени подходит как первоначальный поиск кандидата. В общей базе необходима сохранённая привязка к конкретному аккаунту и remote ID папки.

Схема `GET_EXPORT` не содержит отдельную базу постерного кэша. Наличие JSON-экспорта само по себе не означает полную резервную копию всех офлайн-изображений.

## 2. Rezka Library Firefox 0.5.5 FIXED

Файлы лежат в корне ZIP. Это отдельная браузерная обвязка семейства Library: Promise API, фоновая страница и отдельная страница операции, форматы папок и междоменные ключи.

Фактический manifest — **MV2**, `background.scripts`, `persistent: true`, `strict_min_version: "121.0"` (`manifest.json:25`). В README есть устаревшее упоминание Firefox MV3. Для требуемого Firefox 115 ESR этот ZIP в текущем виде не подходит по ограничению manifest. Одного снижения номера версии недостаточно для подтверждения совместимости: нужно отдельно проверить использованные API и весь сценарий.

Роль: источник адаптера Firefox и совместимости резервных копий; общую бизнес-логику не копировать вторым независимым набором файлов.

## 3. Rezka Library Backup 0.4.5

Папка: `Rezka-Library-Backup-0.4.5/`.

Полезны междоменные ключи, нормализация папок `/favorites/<id>`, сохранение описаний и оригиналов постеров, объединение записей из разных папок, JSON и различные HTML-представления. Важная механика — дополнять уже полученные данные, а не повторно загружать их при каждом экспорте.

Это предшественник более поздних Library. Отдельный движок для него не нужен; нужен адаптер старого формата и проверка восстановления папок, описаний и постеров.

## 4. Rezka Catalog Manager 5.2.17

Файлы в корне ZIP. Это самый богатый источник функций управления библиотекой.

- `background.js:63` — IndexedDB schema 5: фильмы, каталоги, постеры, описания, связи, пользовательское состояние, коллекции и структуры меток.
- `manager.html/manager.js` — большой экран, карточки, поиск, тип/год/статус/каталог/коллекция, сортировки, динамическая подгрузка или страницы.
- `managerSaveState` хранит статус, личную оценку, избранное и заметки; `managerSaveMovie` редактирует метаданные.
- Отдельные пользовательские каталоги, коллекции, добавление/удаление связей, экспорт выбранной коллекции в HTML.
- Различаются рейтинг HDRezka, IMDb, Кинопоиск и личная оценка.
- Сбор каталогов, диапазонов годов, страниц персон, ручное добавление фильма; отдельное обогащение описаниями и постерами.
- Есть журнал, состояние операции, восстановление и остановка.
- `background.js:45–49` — обнаружение Cloudflare/Anubis, сохранение приостановленного задания и показ страницы проверки.
- `background.js:1317` — проверка результата пользовательского прохождения защиты по событиям вкладки и продолжение задания.
- `managerExport` (`background.js:253`) отдаёт `format: "RezkaCatalogManager"`, фильмы и отдельные массивы постеров, описаний, пользовательских состояний, коллекций и связей.

### Ограничения, подтверждённые кодом

1. **Страницы интерфейса не означают постраничное чтение базы.** `managerList` (`background.js:163`) сначала загружает все `movies`, `userState`, `descriptions`, затем фильтрует, сортирует и делает `slice`. При выборе коллекции/каталога также загружает все связи. Заявление README о работе списка через cursor не соответствует этой реализации. Перед переносом на большую библиотеку нужны индексные запросы.
2. **Минимум три параллельных операции.** `saveSettings:31` и `currentConcurrency:921` ограничивают значения снизу числом 3, сверху 10. Это нельзя переносить как настройку по умолчанию с учётом прошлого бана IP.
3. **Часть галочек зеркал не сохраняет смысл выбора.** В `normalizeMirrorEnabled:42` встроенные адреса получают значение из `DEFAULT_ENABLED_MIRRORS`, а не из пользовательского `input`. Нужна исправленная нормализация.
4. **Формирование адресов частично жёстко задано.** `canonicalMovieUrl` использует `rezka.fi`, а `publicMovieUrl` — `rezkery.com`, несмотря на наличие выбора публичного зеркала. В общей модели адрес выбирается при открытии, не путём переписывания идентичности.
5. Структуры `tags/movieTags` присутствуют в хранилище и экспорте. Полный отдельный пользовательский редактор меток не подтверждён исследованным интерфейсом; его следует включить в план как доработку, а не считать готовым модулем.

Возможность обработки 10/50/100 тысяч карточек требует измерений. Такие испытания при этом разборе не проводились.

## 5. Rezka Catalog Saver Pro Auto 4.5.4

Предшественник Manager. Есть IndexedDB с раздельными сущностями, добавление каталога/персоны/одного фильма, сбор метаданных, постеры, HTML, раздельные экспорт и очистка частей базы, журнал и восстановление задания.

Полезен как источник совместимости старых копий и сценариев отдельных операций. Большинство функций развивается в Manager; сохранять два параллельных сканера в общем приложении нецелесообразно.

Повторные попытки и HTTP-зеркала в старом fallback не должны автоматически переноситься на запросы авторизации общего приложения. В плане основной сеанс работает по HTTPS; ошибки защиты останавливают очередь.

## 6. Offline Advanced 1.0.37 Pagination Fix

Папка: `rkfix37/`.

Сильная сторона — проверка реальной навигации и содержимого страницы:

- `background.js:38` — `ensureBrowserContext` и управление вспомогательной вкладкой.
- `scanner.js:278` — `pageSignature`.
- `loadCategoryPage` проверяет, что следующая страница не вернула тот же набор карточек.
- `scanCategory` (`scanner.js:307`) удаляет повторные ID и останавливается, если очередная страница не добавляет новых фильмов.
- Экспорт сохраняет карточки, изображения и стили, содержит фильтры, настройки домена открытия, размера постера, шрифта, числа колонок и ручное добавление.

Ограничение: `needsBrowserContext` (`scanner.js:69`) выбирает браузерный способ по регулярному выражению `hdrezka.*`; `rezkery.com` и `rezka.fi` в него не входят. Для общего приложения выбор транспорта должен зависеть от настроенного сеанса и результата запроса, а не только от части имени домена.

Нормализация базы категории удаляет query. При переносе необходимо сохранять `filter/genre`, иначе разные каталоги могут стать одним источником.

## 7. Offline Advanced 1.1.0

Папка: `advanced/`.

Есть очередь годов, отдельное сохранение завершённой категории, восстановление через alarms/startup, JSON проекта `{version, exportedAt, categories}`, комбинированные HTML-фильтры по названию, году, стране и жанру, темы и выбор числа колонок.

Фактические отличия от 1.0.37:

- `fetchText` в `scanner.js` выполняет прямой `fetch`; механизма `BROWSER_DOCUMENT_HTML` и проверки отпечатка из 1.0.37 здесь нет. Это различие исходников, а не доказанная история релизов.
- README утверждает переход базы на `chrome.storage.local`, однако `db.js:3` по-прежнему открывает IndexedDB, `offscreen.js` вызывает `RKDB.put`, `popup.js` — `RKDB.all`. В storage хранится состояние задания и настроек.
- Обогащение описаниями использует четыре worker и задержку 35 мс внутри каждого. Для объединённого приложения требуется общая регулируемая очередь.
- Данные категории включают готовый HTML карточек и стили. Их импорт требует выделения структурированных полей и очистки фрагментов перед отображением.

Роль: формат старых проектов, очередь по годам и функции автономного просмотрщика. Номер версии не основание заменять сканер 1.0.37 целиком этим файлом.

## 8. Offline Simple 1.1.0

Папка: `simple/`. Сокращённый popup над сходным сканером: шаблон URL, диапазон годов, получение описаний, сохранённые категории, автономный HTML, тема и колонки.

В исследованном popup нет отдельных кнопок JSON-импорта/экспорта, присутствующих в Advanced. Для объединения полезна идея простого режима над теми же данными. Отдельная копия базы и сканера для простого интерфейса не нужна.

## Сопоставление с текущим рандомайзером

Текущая версия уже даёт общий/годовой подбор, категории, количество карточек, базу без повторов, JSON/HTML, Gist и RANDOM. Сохраняются вкладка расширения, параметры и пагинация; на Android — год, режим и состояние базы.

При объединении следует изменить следующие основания:

| Сейчас | Для большой общей библиотеки |
| --- | --- |
| Путь карточки без домена — ключ | Числовой HDRezka ID с алиасами старых путей; путь — запасной ключ |
| Наличие записи в базе исключает фильм из рандома | Библиотека, история подбора и просмотренное — отдельные сущности |
| Массив в `storage.local`, на Android JSON в SharedPreferences | IndexedDB и Room/SQLite с индексами и миграциями |
| Экспорт нормализует ограниченный набор полей | Версионированный контракт, сохраняющий папки, связи, статусы, оценки и описания |
| RANDOM — одна специальная папка | RANDOM плюс остальные папки с отдельной областью синхронизации |
| Длинные браузерные задачи частично находятся в памяти | Сохраняемая очередь и контрольные точки после каждой завершённой единицы |

У текущего Android работа с Drive реализована через системный выбор файла. Это обмен файлом через доступного провайдера документов; отдельная автоматическая синхронизация Google Drive API потребует самостоятельного этапа авторизации и разрешения конфликтов.

## Ограничения платформ и официальные источники

Для Chrome 109 нужен отдельный manifest и проверка возможностей API. Offscreen доступен начиная с Chrome 109; из extension API в таком документе доступен runtime, поэтому обращения к расширению маршрутизируются сообщениями. [Chrome Offscreen](https://developer.chrome.com/docs/extensions/reference/api/offscreen).

Состояние долгого задания нельзя оставлять только в глобальных переменных: service worker может завершиться, после чего значения теряются. [Жизненный цикл Chrome service worker](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle).

Firefox использует фоновую страницу/скрипты; требования старых браузеров исключают один универсальный manifest со всеми вариантами background. Для Chrome 109 и Firefox 115 сохраняются отдельные сборки. [MDN: background и совместимость](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/background).

Для Android предлагается собственный слой хранения Room поверх SQLite и собственный сеанс WebView. Это проектное решение, опирающееся на текущую архитектуру приложения. [Room](https://developer.android.com/training/data-storage/room), [CookieManager WebView](https://developer.android.com/reference/android/webkit/CookieManager).
