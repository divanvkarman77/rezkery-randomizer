# Rezka Suite 2.0.0-alpha.1

Экспериментальная реализация в ветке `research/rezka-mega-suite`. Это отдельная версия общего приложения. Исходные результаты разбора восьми архивов сохранены в соседних документах.

## Что реализовано

| Область | Реализация |
| --- | --- |
| Общая библиотека | Общие `suite/` исходники для четырёх расширений и Android; IndexedDB на desktop, SQLite с индексами и отдельными файлами постеров на Android |
| Идентичность | Числовой `rezka:ID`, алиасы путей и старых ключей; обновление ключа по пути до числового с переносом связей, истории и личных данных |
| Независимые состояния | Известный каталог, история случайного выбора и статус просмотра хранятся отдельно. Полный импорт не исключает всю библиотеку из рандома |
| Импорт | Randomizer, Library, Manager/Saver, Desktop FAV, Offline Advanced JSON; известные HTML-карточки и встроенные данные, основная HTML-часть MHTML; собственный ZIP |
| Большие файлы | Потоковое чтение JSON/HTML, ограниченные буферы, предварительное размещение отдельно от библиотеки, просмотр новых/существующих карточек, подтверждение и отмена |
| Перенос | Общий JSON метаданных, полный ZIP с отдельными постерами и проверками CRC/хеша, автономный HTML, совместимый экспорт истории в старый Randomizer |
| Менеджер | Поиск, год, тип, статус, каталог/коллекция/метка, сортировки, страницы по 60 карточек; оценки, избранное, заметки и редактирование сведений с защитой ручных изменений |
| Рандом из библиотеки | Отдельные параметры простого и расширенного режимов; необязательный год, список и −/+, несколько карточек, разные годы в простом режиме; отдельная история |
| Задания | Сохраняются параметры и следующая страница/запись, пауза/продолжение/отмена, ограниченные повторы, Retry-After, общая остановка Suite при проверке защиты |
| Сайт | Сбор каталога/года/персоны по указанному адресу, действительная пагинация и ручное число; проверка адреса и отпечатка карточек против повторения первой страницы |
| Закладки | Импорт всех папок через сеанс зеркала; отдельное объединение RANDOM с историей или явно выбранным локальным каталогом, последовательная отправка отсутствующих numeric ID; автоимпорт RANDOM |
| Кэш | Импорт встроенных постеров и описаний, отдельное последовательное получение постеров и quick_content, очистка медиа без удаления библиотеки |
| Gist | Объединение метаданных, отдельные варианты конфликтующих заметок/оценок; ограничение до 950 КБ, без изображений и сеансов входа |
| Сборка | Генератор копирует общие исходники в четыре платформенных пакета; Android включает те же исходники как assets |

## Как открыть

- В расширении — ссылка **«Открыть общую библиотеку Suite»** над вкладками старого рандомайзера.
- В Android — кнопка **«Общая библиотека Suite»** на главном экране.
- В Suite сначала откройте **«Файлы»** для импорта либо **«Каталоги и закладки»** для добавления каталога.
- Для резервной копии с постерами выбирайте **ZIP**. JSON содержит метаданные. HTML ограничен 64 МБ; для больших коллекций предназначен ZIP.
- Перед записью прочитанного файла показывается предварительный результат. Опция «считать выбранными» нужна только для намеренного пополнения истории. RANDOM и старая база Randomizer распознаются отдельно.
- После проверки защиты откройте зеркало, завершите проверку и нажмите **«Продолжить»** у задания. Таймер на 15 минут не устанавливается.

## Установка и сохранность рабочей версии

Android alpha имеет отдельный application ID `com.rezkery.randomizer.suite` и название **Rezka Suite (alpha)**. Он устанавливается рядом с рабочим Randomizer. Android изолирует данные приложений: для переноса из рабочего приложения используйте его экспорт JSON и импорт в Suite. Внутри alpha история классической формы и Suite переносится через общий адаптер.

Расширения alpha имеют название Rezka Suite. Если они установлены с другим ID/из другой папки, база рабочего расширения переносится файлом. Обновление в той же папке сохраняет доступ к старому хранилищу и запускает миграцию выбранных карточек. Исходные пользовательские базы и страницы аккаунта в GitHub не добавляются.

## Проверки на присланных материалах

После исправления чтения длинных строк все 10 HTML/JSON-файлов разобраны в процессе Node с пределом heap 256 МБ. Это проверка чтения и нормализации; она не измеряет запись всех изображений в браузерное хранилище или память телефона.

| Образец | Размер | Уникальные карточки | Время чтения, локальный прогон |
| --- | ---: | ---: | ---: |
| JSON каталога 1980–1989 | 123 588 793 байта | 3 873 | 3,9 с |
| JSON проекта 1989–2000 | 244 938 642 байта | 6 218 | 6,4 с |
| Большой автономный HTML 1989–2007 | 431 583 706 байт | 11 708 | 26,7 с |
| HTML Library с описаниями | 34 305 516 байт | 273 | 2,1 с |

HTML Library содержит повторения одной карточки в разных разделах: поэтому число обнаруженных вхождений описаний/постеров может быть больше числа уникальных фильмов. При импорте сохраняется один фильм и отдельные связи.

Из MHTML взята только обезличенная разметка пагинации для тестов: старый общий каталог — 2523 страницы, новые снимки — 2541, фильмы 1990 года — 13, вторая страница папки — 2. Числа берутся из каждого снимка, постоянного лимита 2530/2540 в Suite нет.

Локальное измерение IndexedDB-адаптера на `fake-indexeddb` с одними метаданными: 10k/50k/100k записей; первая страница — 11/9,5/15 мс; сочетание поиска, года и типа — 36/41/52 мс. Это показатели тестового адаптера Node на данном компьютере, а не обещание скорости телефона или старого Firefox. Для нативного адаптера добавлен отдельный прогон 10k/50k/100k в эмуляторе.

Автотесты включают совместимость форматов, повторный импорт, смену зеркала, перенос связей при смене ключа, сохранность личных данных, полный ZIP-цикл, повреждённые файлы, будущую схему, защиту от исполнения импортированного HTML, проверку очереди и повторения страниц. Реальный UI-сценарий проверяет импорт, редактор, режимы, ZIP, повторное открытие и узкий экран; в Chromium дополнительно запускается настоящее расширение с worker.

## Практические границы alpha

- Запросы к реальному аккаунту HDRezka в ходе разработки не выполнялись. Операции закладок и quick_content основаны на изученных исходниках и сохранённой разметке. Различия ответов зеркал требуют проверки после входа на устройстве; сборка сама по себе не подтверждает живую синхронизацию.
- На Android задания выполняются при открытом экране Suite. После пересоздания экрана продолжение идёт с сохранённой точки. Отдельного постоянно работающего сервиса Android в этой версии нет.
- Клавиатура и проверка защиты используют отдельный полноразмерный WebView без нативного моста; cookies Chrome не читаются. Нативный мост существует только на встроенном экране приложения.
- Общая очередь относится к операциям Suite. Одновременные операции классического интерфейса и отдельно установленных старых расширений не координируются с ней.
- MHTML сейчас переносит карточки из основной HTML-части; вложенные MIME-изображения не становятся постоянным кэшем автоматически.
- Поддерживается собственный несжатый ZIP Suite; произвольные архивы расширений ZIP импортом базы не считаются. Один пакет ограничен 4 ГБ/65535 файлами.
- Google Drive OAuth/API, поиск альтернативных оригиналов постеров на зеркалах, пакетный экспорт выбранного поднабора и расширенный режим автономного просмотрщика остаются следующими задачами. Сохранение файла в Drive через системный диалог не называется прямой синхронизацией Drive.
- Windows 7/Chrome 109, Firefox 115 ESR и пользовательский физический Android требуют отдельных испытаний. Все четыре manifest и исходники проверяются и упаковываются, но тест в современном Chromium не заменяет эти испытания.

Полное выполнение всех критериев исходного шестиступенчатого плана пока не объявляется. Этот alpha даёт работающую общую основу и измеряемые проверки для следующего этапа.
